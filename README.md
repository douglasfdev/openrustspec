# OpenRustSpec

**OpenRustSpec** is a powerful, specification-driven code and artifact generation engine written in Rust. It is designed to be the "muscle" behind higher-level tooling, such as LLM-based development assistants, by translating structured OpenAPI v3 specifications into a variety of useful outputs like documentation, development plans, and even source code.

## Core Philosophy

The core idea of `openrustspec` is to separate **intent** from **execution**.

1.  **Intent**: A clear, structured definition of an API, provided as an `spec.yaml` (OpenAPI v3) file. This is the single source of truth.
2.  **Execution**: The `openrustspec` engine, which takes this specification and uses extensible "generators" to produce different artifacts.

This approach makes it an ideal tool for automated workflows, where a specification can be generated by an AI or a developer, and `openrustspec` handles the repetitive task of creating consistent boilerplate, documentation, and plans.

## Workflow

`openrustspec` is project-oriented. All artifacts for a given specification are neatly organized within a dedicated project folder under the `rustspec/` directory.

### 1. Create a Project and Specification

First, create a project directory and place your OpenAPI specification inside it. The default structure is:

```
rustspec/
└── my-awesome-api/
    └── spec.yaml
```

The `spec.yaml` is your OpenAPI v3 specification. For example:

```yaml
# rustspec/my-awesome-api/spec.yaml
openapi: 3.0.3
info:
  title: My Awesome API
  version: 1.0.0
paths:
  /users:
    get:
      summary: List all users
    post:
      summary: Create a new user
```

### 2. Generate Artifacts

Once the specification is in place, you can use the `openrustspec` CLI to generate various artifacts from it. The tool will automatically find the `spec.yaml` inside the project folder.

## How to Use (CLI)

The CLI is invoked via `cargo run`. The main argument is the `project_name`, which corresponds to the folder name inside `rustspec/`.

### Generate a Development Plan

Creates a `plan.md` file with a checklist of tasks based on the API endpoints.

```bash
cargo run -- my-awesome-api --format plan
```

**Output:** `rustspec/my-awesome-api/plan.md`
```markdown
# Development Plan

Based on the API specification, the following tasks are proposed:

- [ ] Implement endpoint: `Get /users` (Summary: List all users)
- [ ] Implement endpoint: `Post /users` (Summary: Create a new user)
```

### Generate Documentation

Creates a `docs.md` file with basic API documentation.

```bash
cargo run -- my-awesome-api --format doc
```

**Output:** `rustspec/my-awesome-api/docs.md`
```markdown
# My Awesome API
Version: 1.0.0

## Endpoints

- `Get` **/users**: List all users
- `Post` **/users**: Create a new user
```

### Generate a Proposal

Creates a `proposal.md` file, which currently mirrors the documentation.

```bash
cargo run -- my-awesome-api --format proposal
```

**Output:** `rustspec/my-awesome-api/proposal.md`

## Future Features (Roadmap)

`openrustspec` is built on an extensible architecture. The following features are natural next steps for its evolution:

-   **Code Generators**:
    -   `RustCodeGenerator`: Generate boilerplate for a Rust web server (e.g., using Axum or Actix-web) directly from the specification.
    -   `ClientSDKGenerator`: Create client-side SDKs in various languages (TypeScript, Python, etc.).

-   **Richer Domain Model**:
    -   Expand the parser and core model to understand OpenAPI `components`, `schemas`, `parameters`, and `requestBody`/`responses`. This will allow for the generation of data models (structs, interfaces) and more detailed endpoint logic.

-   **Task Management Integration**:
    -   A `TasksGenerator` that outputs a `tasks.json` file, which can be consumed by project management tools or other automated agents.

-   **Plugin System**:
    -   Develop a plugin architecture to allow third-party developers to create and share their own generators without modifying the core engine.

-   **Interactive Mode**:
    -   An interactive CLI mode that guides the user through applying changes, selecting tasks, and generating code step-by-step.

-   **Testing Generator**:
    -   A `TestGenerator` that creates skeleton test files (e.g., using Postman collections or integration test templates) for each endpoint defined in the specification.
